# Política de seguridad

## Alcance

Esta política cubre el código y la infraestructura de `cbsdev.lat`, incluyendo la aplicación Next.js, el endpoint de imágenes, el Dockerfile y los flujos de publicación.

El contenido educativo se revisa por exactitud, pero no constituye asesoría profesional ni una garantía de seguridad para terceros.

## Cómo reportar una vulnerabilidad

No publiques detalles explotables en un issue, pull request o red social.

1. Usa el reporte privado de vulnerabilidades de GitHub: **Security → Advisories → Report a vulnerability**.
2. Si esa opción no está disponible, contacta a [@chrisq-dev](https://github.com/chrisq-dev) por GitHub sin incluir datos sensibles ni instrucciones de explotación en un canal público.
3. Incluye una descripción del impacto, pasos mínimos para reproducirlo, versión o URL afectada y una propuesta de mitigación si la tienes.

## Qué puedes esperar

- Confirmación de recepción cuando sea posible.
- Evaluación del alcance y la severidad.
- Crédito en la corrección si lo deseas.
- No se tomarán represalias por reportes realizados de buena fe.

## Fuera de alcance

- Ataques a terceros, denegación de servicio o acceso a datos sin autorización.
- Pruebas en sistemas que no pertenezcan al proyecto.
- Reportes generados únicamente por escáneres sin impacto demostrable.
